2026-10-13 — Session D: workout data model and storage
- src/storage/types.ts: Workout { id, name, exercises[], workSeconds,
  restSeconds, loops, loopEnabled, restBetweenLoopsSeconds } plus NewWorkout
  (the same without an id, which is what the editor hands over).
- THE STORAGE INTERFACE IS ASYNC ON PURPOSE. KeyValueStore returns Promises
  even though localStorage is synchronous, because @capacitor/preferences —
  the documented replacement — is Promise-based. A synchronous interface here
  would have made that swap a rewrite of every caller instead of one new
  class. Sessions E and G must therefore await the store.
- src/storage/keyValueStore.ts: KeyValueStore interface; WebKeyValueStore
  (takes any Storage-shaped object, defaults to localStorage);
  MemoryKeyValueStore (tests, and the fallback); createDefaultStore() probes
  localStorage with a write and falls back to memory, because localStorage
  throws rather than returning null when site data is blocked.
- src/storage/workoutStore.ts: listWorkouts, getWorkout, saveWorkout (creates
  when there is no id, updates in place when the id is known), deleteWorkout
  (returns whether anything went), getLastUsedWorkoutId / setLastUsedWorkoutId,
  getLastUsedWorkout (last used -> first saved -> null, so Home always has
  something to select), seedIfEmpty.
- Validation: name required, >= 1 exercise, no blank exercise names, work and
  rest >= 5s, loops >= 1, all whole numbers. restBetweenLoopsSeconds is 0 for
  off, otherwise >= 5 — 0 is a documented value, not a validation failure.
  validateWorkout returns EVERY problem, not the first; saveWorkout throws
  WorkoutValidationError and writes nothing.
- createId prefers crypto.randomUUID, falls back to getRandomValues, then to
  timestamp+random. randomUUID needs a current WebView and the A32's System
  WebView version is not ours to choose.
- Corrupt or foreign data in storage degrades to an empty library rather than
  throwing: bad JSON, a non-array payload, and non-workout entries are all
  dropped on read. Better an empty library than a screen that will not load.
- Seed "Core 15": 5 exercises named "Exercise 1".."Exercise 5" (placeholders,
  as the card specifies — real names come from the editor in Session E),
  45s work, 15s rest, 3 loops, between-loop rest off. Seeds once only and
  points last-used at it.
- Tests: 42 passing across 4 files, up from 1. Covers save/load/update/delete,
  ordering, id uniqueness, name trimming, last-used pointer behaviour
  (including clearing it when its workout is deleted and falling back when it
  is stale), seeding once only, reload persistence, corrupt payloads, the
  validation matrix including the 5-second boundary exactly, and a full
  round trip through WebKeyValueStore — the production path, which the
  in-memory tests would otherwise have left unexercised.

2026-10-13 — Session F: timer engine
- src/engine/sequence.ts: buildSegments(workout) -> flat Segment[]:
  leadIn (5s), then work per exercise per loop, a rest after every work
  except the very last, and at a loop boundary a 'loopRest' in place of the
  rest when restBetweenLoopsSeconds > 0 — same rule as duration.ts, and a
  test pins the two together. Segment = type, durationSeconds, exerciseName,
  nextExerciseName, loop, totalLoops, exerciseIndex.
- Naming convention: for work, exerciseName is the exercise being done and
  nextExerciseName the next one worked (null at the very end). For leadIn
  and rests both name the UPCOMING exercise, and loop/exerciseIndex refer to
  it — so a rest before loop 2 reports loop 2. Built for "Rest. Next up: X".
- src/engine/timer.ts: WorkoutTimer with start/pause/resume/stop,
  getState() (status, segmentIndex, segment, secondsRemaining rounded up,
  segmentProgress, progress, elapsedMs) and events segmentStart,
  countdownTick(3|2|1), workoutComplete, plus 'tick' every wake-up for
  redrawing. Elapsed = clock.now() - start, less pauses; segment ends are
  precomputed integer ms. The interval (100ms default) only decides how often
  the clock is read.
- Injectable Clock { now, setInterval, clearInterval }; systemClock uses
  performance.now. No React or Capacitor imports in src/engine.
- Late wake-ups (throttled WebView): only the segment now current gets a
  segmentStart, and a countdownTick only for the current second. Stale cues
  are dropped, not burst. A throwing listener is logged and the clock goes on.
- Tests: 83 passing (18 new). Covers the 5x45/15x3 sequence (14:45 + 5s
  lead-in = 14:50), names/loops/indexes, between-loop rest, loop off,
  event timing incl. 3-2-1 at exact ms, pause/resume, stop/restart, slept-
  through cues, a throwing listener, and 15 simulated minutes with jittery
  ticks and 1-1.5s stalls: every boundary fires late by < one wake, never
  early, and elapsed ends at exactly 890000 ms.
- MUTATION CHECKED: resume forgetting paused time (2 fail), a 1%-slow
  tick-quantised clock (7 fail), final rest not skipped (12 fail), countdown

INSTALLING GYMTIME ON THE PHONE
  Build:  npm run android:apk
          -> android/app/build/outputs/apk/debug/app-debug.apk (~4.9 MB)
  Option A — USB (developer mode, USB debugging on):
          adb install -r android/app/build/outputs/apk/debug/app-debug.apk
          adb is at %LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe.
          -r keeps saved workouts and settings when updating.
  Option B — no cable: copy app-debug.apk to the phone (Google Drive,
          email, USB file transfer), open it in My Files, and allow
          "Install unknown apps" for that app when Android asks.
  Then open GymTime from the app drawer. Updates install over the top; an
  uninstall deletes saved workouts. The APK is debug-signed: fine for
  sideloading, not for the Play Store.
